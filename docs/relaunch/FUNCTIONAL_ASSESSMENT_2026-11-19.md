# CGT Tracker functional assessment and release fixes

**Decision — hold the paid launch.** The modern ordinary-share engine matched an independent reference across 2,000 generated portfolios. Specific, reproducible inputs still produced incorrect gains that could be marked complete and exported. The first fixes are historical cost basis, duplicate broker executions and the currency basis of Interactive Brokers trades. A deployment that changes the arithmetic also needs to retire affected saved reports.

Assessed 18–19 November 2026. Railway staging served commit `0d00c40a443911f2ed2f6d2848b01fff37ca2aa3`. New calculations used engine `2.0.0-alpha.3`. Some existing staging reports were originally saved under `2.0.0-alpha.2`. Browser observations below identify the environment used. All monetary examples are synthetic. [Staging](https://web-staging-e003bc3b.up.railway.app/) · [Build and readiness evidence](../../.private/functional-audit-current/hosted/release.json)

## Remediation on the relaunch branch

The findings below describe the assessed build. Engine `2.0.0-alpha.4` uses exact proportional costs, checks the position at the sale date and requires a personal ownership and residence declaration. An affected historical holding needs a professionally reviewed opening position before it can produce a complete gain. The original historical example produces a blocked draft without that evidence and a £900 gain with its verified £100 opening cost. The fractional example gives £4.61. Old report IDs are withdrawn from download and purchase while the underlying snapshots and receipts remain available for audit. [Calculation and rounding review](TAX_REVIEW.md) · [Reviewed opening balances](REVIEWED_OPENING_POSITIONS.md)

IBKR now checks external account and execution identity at preview and commit. Retrying the native executions through the template preserves the £71.62 gain. The mixed-currency fixture reconciles to £128.92 using supported sterling rates. A zero-proceeds disposal, a trade-shaped cash entry or a conflicting FX statement cannot silently become a tax result. The dated matrix identifies native, assisted and unsupported variants for all six brokers. [Broker evidence and recovery](BROKER_SUPPORT.md)

Purchase eligibility, partial-year totals, original Unicode references, import-field recovery, preview selection, scenario labels, saved profile names and contact submission were corrected. Report downloads carry the recorded scope declaration and any reviewed opening evidence. Staging and operator procedures cover older results, mapped sandbox billing transitions, export and erasure requests and restore replay. [Release criteria](REVIEW_READY.md) · [Billing evidence](BILLING.md) · [Account requests](ACCOUNT_REQUESTS.md)

Separate production decisions include independent tax review, primary source records for the outstanding broker variants, publication of the required customer disclosures, and a restore/alert test on the intended production services. The existing sandbox and staging evidence is recorded separately from those decisions.

## Report, purchase and interface changes

1. **Protect the selected purchase.** A sale missing its acquisition basis has no annual gain. The summary for that case is still eligible for report-targeted checkout, and a subscribed user receives a PDF headed “Total pending acquisition history”. The file is marked draft. Before offering the £49 plan for that result, explain exactly what is missing and link to correction. Either block that purchase until a result exists, or require an explicit informed choice for a draft. Keep the free CSV, useful draft evidence and existing subscribers' access clearly labelled. Test direct report links, billing preflight and the return from checkout. [Eligibility and generated reports](../../.private/functional-audit-current/surfaces/workspace.json)
2. **State the period covered by a zero.** A saved 2025–26 portfolio with an October sale said “No disposals in this tax year” when calculated only through June. The recovery prompt suggested uploading sales that were already present. Use “No disposals through 30 June 2025”, show that later imported activity exists and offer to extend the cutoff. Preserve the correct full-year empty state. [Actual summary](../../.private/functional-audit-current/surfaces/partial-year-summary.txt)
3. **Preserve evidence references in paid PDFs.** The distinct execution references 東京 and 大阪 both became “??”, and the account label 取引口座 became “????”. CSV preserved the strings. Embed suitable font coverage or provide a documented lossless representation. Test text extraction, printed rendering, uniqueness and cross-reference back to the receipt. [PDF text](../../.private/functional-audit-current/surfaces/unicode-evidence.txt)
4. **Make the import error recoverable at its field.** An invalid ISIN check digit blocks the trade but leaves the input marked valid, loses focus and gives advice about tickers. Link the message to the ISIN, focus the input and retain the other contract-note values. Keep the existing fee-correction behaviour, which stayed on the correct row and explained the difference.
5. **Resume the intended file.** With two previews for the same account, Overview silently resumes the newest file. Display the filename for one pending file and offer a choice when there are several. Give the broker guide a direct route to upload with the relevant account context.
6. **Clarify outcomes and failures.** Lead mobile Calculations with the result, cutoff and confirmed-account count. Keep the full list expandable and incomplete coverage prominent. Show a known instrument name alongside its ISIN in price scenarios. On a failed report read, offer to reload that report. Reserve warnings about duplicate uploads for interrupted writes.
7. **Finish the remaining accessibility and copy polish.** Link signup wording to supported files. Keep the mobile tax-year range together. Improve the closing homepage paragraph's measured 4.41:1 contrast behind the white dots, and hide duplicated broker initials from screen readers. The original brand, layout and interaction patterns can accommodate these changes. [Full staging UI review](../../.impeccable/critique/2026-11-18T23-43-34Z__src-app.md)

8. **Refresh the account name throughout the app.** Settings saved the new name and confirmed success. The sidebar showed the old name until a reload. Update the shared session display on success, while keeping an unsaved edit local to its tab. The same test confirmed old-password rejection, acceptance of the new password and revocation of the other signed-in session. [Settings results](../../.private/functional-audit-current/surfaces/settings.json)

9. **Protect a support message while the page loads.** With the staging JavaScript bundles delayed, the contact form allowed submission on desktop and mobile WebKit. Both browsers reloaded, cleared the fields and issued zero application POSTs. There was no delivery or error notice. Provide a working server form action or keep submission disabled until the handler is ready and explain the alternative support email. Test delayed scripts and a normal successful submission. ## Implementation order and release acceptance

1. **Stop incorrect results from being sold.** Start with guards for affected historical disposals, contradictory or unknown IBKR base currency and repeat executions, plus an eligibility check for obsolete or unreliable saved runs. Add the observed reproductions as regression tests first. Verify that safe, unaffected reports can still be downloaded.
2. **Correct the engine, input rules and public estimates.** Implement the agreed proportional-cost representation, residency/ownership and opening-holding safeguards, market-value and contradictory-cash review, Scottish band handling and common monetary presentation. Retain the independent oracle and target exact ties deliberately. Have an independent UK CGT reviewer sign off the historical treatment, FX and allowable fees, annual rounding and the distinction between a gain and a tax estimate. [Reviewer pack](TAX_REVIEW.md)
3. **Reconcile existing portfolios without destroying evidence.** Dry-run a scan for affected histories, broker accounts, execution aliases, rates and published versions. Compare old and corrected figures by tax year, preserve receipts and surface unresolved evidence. Prove that a corrected result replaces the active report on both WebKit profiles and that a stale paid link cannot serve the old amounts.
4. **Qualify the advertised broker exports and report formats.** Add raw byte-level specimens and primary supporting documents where available. Keep unsupported activity blocking. Recheck six brokers, overlapping exports, multi-account imports, loss/zero/provisional years, FX, foreign references and the on-screen/PDF/CSV reconciliation.
5. **Finish the paid service rehearsal.** The current runtime deliberately accepts sandbox keys only. Before a separately authorised live release, establish ownership of any legacy Stripe entitlements, rehearse the £49 annual mapped-account renewal/decline/3DS/recovery/dispute sequence through to PDF access, and document the operator recovery path for ambiguous requests and risk holds. The earlier provider-only simulations, initial app checkout, refund and automated event tests are useful evidence at different layers. Verify webhooks, cancellation and customer communications in the intended production configuration. The supplied commercial position is PSL Digital, £49 per year, not VAT registered. [Billing evidence and outstanding work](BILLING.md)
6. **Close production operations and notices.** Finalise privacy, retention, cancellation and business disclosures on the customer-facing pages. Rehearse a verified access/deletion request across financial records, billing and backup retention. Settings routes these requests to support today. Repeat the backup, isolated restore and external alert drill on the intended production services. Keep production DNS and live keys behind the owner's separate launch decision. [Production gates](REVIEW_READY.md) · [Account and retention workflow](API_CONTRACT.md)
7. **Final acceptance.** Re-run the financial counterexamples, all six tax-year boundaries, independent-model checks, database and browser suites. Repeat signup through paid download on desktop and mobile WebKit. Compare actual file contents and source references. Record previously saved and freshly recalculated report outcomes separately.
